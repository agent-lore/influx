# Tier 1 (summary) failures are not recovered by the repair sweep

The repair sweep recovers a repair-needed note's missing full text (Tier 2)
and deep-extract sections (Tier 3), but deliberately does **not** re-run Tier 1
(the `## Summary` LLM summarization). Tier 1's only input is the candidate
*abstract*, and — unlike Tier 2's input (the archive, re-downloadable by note
identity) and Tier 3's input (the extracted full text, persisted as
`## Full Text` or re-derivable from the archive) — the abstract is never
persisted in the note and has no durable source to re-fetch: arXiv would need a
new by-id metadata fetch, and an RSS feed summary is gone once the item scrolls
out of the feed. A Tier 1 failure is a rare, cheap, usually-transient LLM error
(see `Cascade._run_tier1`'s defensive degrade-to-repair path), so the item is
written abstract-only with `influx:repair-needed` and the failure is treated as
a create-time concern — not something to heal by re-fetching a possibly-vanished
abstract in a later persisted-note sweep.

## Consequences

- A note flagged for a Tier 1 failure keeps `influx:repair-needed` and its
  `## Summary` is not regenerated by the sweep. This is intended, not a gap.
- Finding 3b therefore moves only the *archive* re-download identity onto the
  Source seam (`Source.archive_download_identity(note)`); it does **not** add a
  `Source.reacquire -> Acquired` path, because there is no durable Tier-1 input
  to re-hydrate.
- If durable Tier 1 recovery is ever wanted, the cheap route is to **persist the
  abstract** on the note at create time (any re-run then reads it locally, and
  RSS becomes recoverable too) — not to add per-source re-fetch.
